# FishSite: план реализации Django Unfold Admin Panel

Исследование: **10 октября 2026 года**; первоначальная браузерная приёмка кабинета — **12 октября**. Статус на **15 октября 2026 года**: **панель и интеграционные действия реализованы, отдельный живой контур проверен. По запросу владельца замена каталога завершена, 39 новых карточек опубликованы с согласованными демонстрационными материалами; временная основная HTTPS-демонстрация через ngrok и все потоки включены**. Постоянный production-ввод остаётся отдельным этапом. Ниже сохранены требования к интерфейсу и приёмке; демонстрация не означает выполнения всех критериев постоянной эксплуатации.

План основан на исследовании рабочей копии FishSite и официальной документации от указанной даты. Он описывает кабинет владельца: интерфейс, редакционные модели, роли, вход, действия и приёмку. Требования ниже сохраняются как контракт; подтверждённые результаты и границы временного ввода приведены в разделах 8–9.

Связанный документ: [план интеграции МойСклад](MoySklad-plan.md). Внешние связи, API, синхронизация прайса, экспорт заявок, очередь и вебхуки реализованы. GET кабинета читает локальную диагностику, POST ставит фоновые действия. Контрольный экспорт, вебхук цены и изменение учётного статуса проверены 15.10.2026 в отдельной БД; её вебхук и туннель отключены. После этого включена новая основная временная демонстрация с собственным активным вебхуком: все четыре потока разрешены в БД, экспорт явно начат после исторических заявок. Флаги окружения по умолчанию остаются `False`; команды — в [руководстве обмена](moysklad-operations.md), результат замены и демонстрационное оформление — в [проверке ассортимента](MoySklad-catalog-review.md).

## 1. Целевой результат и границы

### Реализованная часть и текущие ограничения

- Владелец работает через Unfold в роли обычного `is_staff`, без `is_superuser`; предусмотрена одна прикладная группа «Владелец». Существующий superuser остаётся для технического обслуживания.
- Владелец может редактировать оформление товаров, цену за кг, фото, публикацию, порядок и SEO; хиты продаж явно выбирает и переставляет в двух позициях секции «Рекомендуемые товары» главной.
- Через CMS редактируются существующие тексты и изображения информационных страниц, тексты главной и общие контакты/график. Отдельных настроек обложки нет; кнопка «Перейти к ассортименту» всегда ведёт на `#assortment`. Юридические тела документов остаются в Markdown и read-only архиве согласий.
- Заявки принимаются и хранятся в Django. Наличие подтверждает менеджер; кабинет не проверяет и не списывает остатки. Цена принятой заявки хранится отдельным неизменяемым снимком.
- МойСклад показывает фактическую локальную диагностику; без конфигурации — «Не подключено». Текущая цена сайта редактируется в карточке. Новое внешнее значение и принудительная сверка заменяют ручное, обычное чтение неизменной цены сохраняет его. Переключатели режимов не нужны.
- Для входа настроены TOTP и защита от перебора по учётной записи и IP. При первом входе владелец регистрирует устройство 2FA и сохраняет резервные коды.

Команды миграции и подготовки аккаунта владельца приведены в разделе [«Включение и ручная приёмка»](#10-включение-и-ручная-приёмка). При первоначальной реализации новые тесты админки не добавлялись по решению заказчика; ручные проверки с OTP выполнены 12 и 15 октября в отдельных контурах. Заключительный полный набор проекта прошёл 321/321. 15.10.2026 после backup с проверкой восстановления в рабочую `fishsite` применены шесть добавочных миграций интеграции, Owner получил 43 разрешённых права. Для временной демонстрации 39 карточек уже опубликованы с явно помеченными иллюстрациями; постоянные материалы, юридические сведения и production HTTPS остаются при вводе в постоянную эксплуатацию. Результаты и инструкция — в [руководстве](backoffice.md).

Владелец оформляет ассортимент и содержание сайта через простой кабинет в стиле FishSite. Он видит новые заявки и состояние обмена, может исправить оформление товара и выполнить разрешённое действие без доступа к техническим настройкам.

| Область | Решение |
|---|---|
| Товары | Публичное название, тексты, галерея, категория, публикация, порядок, SEO |
| Рекомендации | Явный выбор двух товаров для главной и их порядка |
| Заявки | Контакты и неизменяемые позиции только для чтения, состояние передачи и учётный статус |
| Контент | Владелец самостоятельно меняет тексты главной, тексты и предусмотренные изображения информационных страниц, контакты, график и условия доставки через раздел «Содержание сайта» |
| МойСклад | Простой экран владельца: состояние обмена, сопоставление товаров и обновление цен; подробности и управление обменом — на отдельном техническом экране |
| Цена | Одно поле «Цена за кг», редактируемое владельцем; новая внешняя цена либо принудительная сверка заменяет его значение |
| Доступ | Владелец без superuser, отдельные права на действия, HTTPS, ограничение попыток входа и 2FA |
| Остатки | Не отображаются и не управляются; наличие подтверждает менеджер |

Розничные и оптовые цены ведутся в МойСклад. Публичный сайт использует розничную цену; оптовая форма остаётся контактной, без корзины и прайса. Оплата, резервы и отгрузки в кабинете сайта не добавляются.

Кабинет сохраняет Django Admin и серверные шаблоны внутри существующего модульного монолита. Отдельное клиентское приложение и публичный REST API не требуются. Сейчас сайт принимает заявки локально и передаёт их менеджеру для подтверждения наличия; экспорт выполняется после отдельного явного запуска владельцем.

## 2. Исходное состояние и необходимые дополнения

Исходная точка проверена при исследовании 10 октября 2026 года, включая незакоммиченные изменения рабочей копии. Итог реализации сверяется с кодом ниже; интеграционные функции добавлены 15 октября; рабочая приёмка остаётся отдельным этапом.

| Уже есть | Где | Как использовать |
|---|---|---|
| Django 5.2.17, Python 3.13, стандартный admin | `pyproject.toml`, `fishsite/settings.py` | Добавить Unfold без обновления Django ради темы |
| Товар, плоская категория, цена/кг, публикация, галерея | `catalog/models.py`, `catalog/admin.py` | Сохранить ID, slug, фото, formset-проверку одного основного изображения |
| Неизменяемые позиции и read-only заявки | `orders/models.py`, `orders/admin.py`, `inquiries/admin.py` | Дополнить служебной обработкой, не разрешая менять историю |
| Фиксированные страницы, текстовые блоки и SEO страниц | `content/models.py`, `content/admin.py` | Удобные формы поверх существующих моделей |
| Архив редакций согласия | `content/consent_revisions.py`, модели заявок | Read-only история; юридические тексты остаются в Markdown |
| Почтовая очередь и административный повтор | `integrations/notifications/`, `integrations/admin.py` | Сохранить действующий сценарий и независимость от МойСклад |

Добавлены Unfold, группа владельца, обязательная OTP-защита, ручной порядок и популярность, SEO товаров/категорий, структурированные контакты/график, два управляемых слота рекомендаций и сведения о последнем изменении цены. Отдельная история цен и отдельные настройки обложки исключены по решению владельца; тексты главной остаются редактируемыми, кнопка ведёт на `#assortment`.

Интеграционный реестр, обмен ценами, результаты проходов и экспорт добавлены по [плану МойСклад](MoySklad-plan.md). Без конфигурации показывается «Не подключено»; диагностика не подменяет живую приёмку.

## 3. Владение данными и контракт с интеграцией

| Данные | Главный источник | Поведение второго приложения |
|---|---|---|
| UUID, артикул, учётное название, единица учёта | МойСклад | Django хранит служебную копию и показывает её для справки |
| Розничный прайс | МойСклад | Успешная синхронизация обновляет цену сайта; при сбое сохраняется текущее локальное значение |
| Оптовый прайс | МойСклад | В первом релизе сайт его не использует |
| Название на сайте, slug, тексты, фотографии | Django | Синхронизация их не перезаписывает |
| Категория сайта, порядок, публикация, рекомендации главной | Django | Классификация склада не меняет навигацию магазина |
| Цена сайта, изменённая в админке | То же поле цены в Django | Действует до нового внешнего значения либо принудительной сверки; внешний прайс не меняется |
| Исходная заявка и её снимки | Django | В МойСклад создаётся учётный документ на её основе |
| Статус продажи, согласованный состав, фактический вес и итог после передачи | МойСклад | Django показывает только учётный статус с датой проверки; исходную заявку не переписывает |
| Исходные заявки и снимки | Django | Только чтение; назначений, внутренних заметок и отметок просмотра нет |
| Состояние экспорта и повторы | Django | Не смешивается со статусами «подтверждён», «отгружен» и т. п. |

Один товар МойСклад соответствует одной карточке сайта. Изменение учётного названия не меняет публичное название и URL. «Восстановить название из МойСклад» допустимо отдельным осознанным действием.

### Граница реализации

| Возможность | Реализуется в этом плане | Предоставляет план МойСклад |
|---|---|---|
| Связь товара | Экран кандидатов/сопоставления, оформление и подтверждение | Реестр `MoySkladProduct`, проверки UUID/единицы/цены, сервис изменения связи |
| Цена | Поле «Цена за кг», подсказка, последнее изменение, право `change_product_price` | Общий сервис сохранения, ревизия и правила синхронизации |
| Обновить цены / повторить передачу | Защищённые действия, сообщения о ходе и результате | Сохранение задачи, дедупликация, retry, неизменный `syncId` |
| Заявки | Просмотр карточек, поиск и фильтры | Снимки, `MoySkladOrderLink`, состояние передачи и учётный статус |
| Мониторинг | Дашборд, списки ошибок, время проверки и охват | Локальные результаты сверки, очередь, heartbeat, безопасные коды ошибок |

Дашборд и формы не вызывают API МойСклад при рендеринге. Фоновые действия возвращают подтверждение постановки и затем показывают результат из БД. Права проверяются сервером, а не только видимостью кнопки.

Базовое оформление и контент можно реализовать до готовности интеграции. Внешние данные в этом режиме обозначаются «Не подключено», зависимые действия недоступны с объяснением. До подключения источника владелец редактирует существующую локальную цену. После подключения поле остаётся доступным, а успешная синхронизация обновляет его автоматически. Общий сервис сохранения и защита от гонок должны быть готовы до включения синхронизации.

## 4. Экраны и настройка Django Unfold

При исследовании 10.10.2026 выбран `django-unfold 0.108.0` для Python 3.13 и Django 5.2; версия закреплена в `pyproject.toml` и lock-файле. Интеграция с FishSite реализована, существующие формы и OTP проверены в браузере 12.10.2026; ручные интеграционные действия дополнительно проверены 15.10.2026. [Релиз и требования](https://pypi.org/project/django-unfold/).

### Навигация

| Раздел | Содержимое |
|---|---|
| Обзор | Новые заявки, опубликованные товары без фото, быстрые переходы и честный статус интеграции |
| Товары | Карточки сайта, редактирование цены, категории, фотографии и публикация |
| Заявки | Розничные и оптовые, раздельные вкладки |
| Содержание сайта | Главная, рекомендации, страницы, контакты и график, SEO |
| МойСклад | Состояние товаров, цен и заявок, кандидаты, связи и сверки; техническая диагностика, потоки и одобрение передачи доступны только superuser |

Группы Django, сессии, сырые очереди, ключи, технические ID и настройки инфраструктуры не нужны в ежедневном меню владельца. Их доступность ограничивается правами на сервере, а не только скрытием ссылок.

### Главный экран

Первый экран отвечает на три вопроса: появились ли заявки, какие товары надо оформить, работает ли обмен.

Показывать счётчики со ссылками: «Новые розничные», «Новые оптовые», «Нужна помощь с передачей», «Товары без фото». Ниже — последние заявки и проблемы, требующие действия. Статус прайса содержит время проверки и охват, например «Проверено 38 из 40 товаров; 2 требуют настройки».

Основные кнопки: «Открыть новые заявки», «Добавить из МойСклад», «Проверить цены». Последняя запускает фоновую задачу и показывает её результат; она не удерживает HTTP-запрос до конца импорта.

### Список и карточка товара

Список: миниатюра, название сайта, артикул, категория, цена сайта, источник цены, публикация, результат синхронизации. Поиск по публичному и учётному названию, артикулу. Фильтры: опубликован/скрыт, категория, нет фото, не связан, ошибка цены.

Карточка имеет понятные вкладки:

| Вкладка | Действия |
|---|---|
| На сайте | Название, категория, краткое/полное описание, публикация, порядок |
| Фотографии | Загрузка нескольких файлов, миниатюры, основное фото, alt-текст, порядок |
| Цена | Редактируемая «Цена за кг», сведения о последнем изменении; подсказка об автоматическом обновлении и время проверки МойСклад после подключения |
| Поиск и SEO | Заголовок, описание, preview поискового сниппета, slug с предупреждением об изменении URL |
| МойСклад | Учётное название, артикул, единица, состояние связи, кнопка открытия исходной позиции |

Основные действия — «Сохранить», «Посмотреть на сайте», «Скрыть/Опубликовать». Для черновика — защищённый предварительный просмотр только сотруднику; нельзя делать скрытый товар общедоступным ради preview.

Сохраняются действующие ограничения на одно основное фото. Проверять формат, размер и разрешение загружаемых изображений, давать понятные ошибки. Сортировка перетаскиванием имеет альтернативу кнопками/полем порядка. Скрытый товар не появляется в поиске, рекомендациях, меню и прямом публичном URL.

### Рекомендации и хиты продаж

На главной сохраняются два места под рекомендации, но владелец выбирает товары и их порядок явно. В выборке — только доступные для публикации товары. Если выбранный товар скрыт, слот перестаёт его показывать; кабинет объясняет причину, случайной замены нет. При миграции можно сохранить текущие два товара как первоначальный выбор.

Выбор этих двух товаров — единственный механизм хитов продаж. Метка «Хит» выводится только в секции «Рекомендуемые товары» главной. В категориях нет фильтра или меток хитов; `?popular=1` не изменяет ассортимент и пагинацию. Отдельная отметка в редакторе товара не предлагается. Прежнее поле `Product.is_popular` сохранено в схеме для совместимости и не влияет на публичный показ. Автоматическую аналитику покупок не добавлять.

### Заявки

В списке розничных заявок: номер, дата, контакт, способ получения и предварительная сумма; карточка показывает неизменяемые позиции, контакты и согласие. Полей для редактирования, назначений, заметок и отметок просмотра нет. Передача и учётный статус отображаются по локальной связи МойСклад; наличие подтверждает владелец.

Снимки и факт согласия доступны только для чтения; сохранение и удаление заявки через админку запрещены. Причины ошибки формулируются по делу: «Не выбран розничный прайс», «Товар не связан», «Нет доступа к МойСклад». HTTP-коды и ID доступны специалисту в подробностях.

Оптовые заявки доступны только для просмотра, поиска по контактам/номеру и фильтрации по дате. Назначений и внутренних заметок нет. Локальных состояний «Новый», «Связались», «Закрыт» нет; дашборд показывает общее число розничных и оптовых запросов. Форма опта не содержит товарного состава для автоматического экспорта.

### Контент и оформление

Основой редактора служит единый `ContentPage.body`; прежние `ContentSection` остаются архивом. Вместо технических ключей показывать формы «Главная», «О компании», «Условия доставки», «Контакты». Контакты и график хранить в структурированных общих настройках и использовать повторно на нужных страницах.

Редактирование контента — обязательная возможность первого релиза, доступная владельцу без разработчика, изменения файлов или подключения к МойСклад. Минимальный сценарий: «Содержание сайта» → выбрать страницу → изменить поля → «Сохранить» → «Посмотреть на сайте». Сохранение сразу обновляет опубликованную страницу, без отдельного процесса согласования.

| Раздел | Что владелец может изменить |
|---|---|
| Главная | Единственный текст в секции «О компании»; заголовок страницы и SEO отдельно. Остальная композиция и подписи фиксированы; кнопка всегда ведёт на `#assortment` |
| Рекомендуемые товары | Два выбранных товара и их порядок по правилам раздела рекомендаций |
| О компании | Единый текст страницы; заголовок и SEO отдельно |
| Доставка и самовывоз | Информационные тексты об условиях доставки и самовывоза; редактирование текста не меняет программные правила расчёта или геометрию карты |
| Контакты | Только общие настройки: телефон, график, адрес и ссылки. Запись contacts скрыта из редактора страниц и его прямых форм |
| Общие данные сайта | Контакты и график в шапке, на главной и странице контактов; добавляемые ссылки с названием, URL и логотипом. В подвале только навигация и подпись |
| SEO | Заголовок и описание для поисковиков на редактируемых страницах; дополнительные настройки свернуть по умолчанию |

Формы показывают привычные названия и короткие подсказки. Для текста достаточно обычных полей с сохранением абзацев; HTML и технические ключи владельцу не нужны. Для изображений — загрузка, миниатюра, замена, alt-текст и понятные ограничения. Изменение содержимого сохраняет существующую вёрстку и адреса страниц.

На этапе реализации составить перечень редактируемых блоков по действующим шаблонам. Каждый указанный выше элемент должен читать сохранённое значение из БД: одного поля в админке без подключения к публичному шаблону недостаточно. Перенести текущие тексты и ссылки без изменения смысла; не заполнять отсутствующие сведения вымышленными контактами или условиями. Обязательные поля проверять до сохранения, а для необязательных явно определить поведение пустого значения. При наличии кеширования сохранение должно сбрасывать соответствующий кеш.

Отдельная модель и форма «Обложка главной» удалены. Заголовок, вводный текст и подписи преимуществ главной остаются в существующих блоках содержания. Кнопка «Перейти к ассортименту» и её ссылка `#assortment` закреплены в шаблоне. Произвольный конструктор страниц и слайдер не требуются.

Юридические тексты сейчас принадлежат Markdown-файлам и архиву редакций. Их не превращать незаметно в обычные редактируемые блоки: кабинет показывает ссылку и пояснение о процессе обновления.

Кабинет использует логотип, тёплые нейтральные поверхности, латунный акцент и локальный Golos Text. Рабочие таблицы — на спокойном однотонном фоне; светлая тема по умолчанию, тёмная по выбору. Цвет статуса сопровождается текстом. Сохранение сообщает результат, ошибки стоят рядом с полем, фокус видим. Проверить 375/768/1280/1440 px, клавиатуру и увеличение масштаба.

### Техническая настройка Unfold

- Добавить `unfold` перед `django.contrib.admin`; перевести используемые `ModelAdmin` и inlines на классы Unfold, сохранив собственные проверки и запреты. [Установка](https://unfoldadmin.com/docs/installation/quickstart/).
- Дашборд: `templates/admin/index.html`, `DASHBOARD_CALLBACK`, запросы с учётом прав и без вызовов внешнего API. [Дашборд](https://unfoldadmin.com/docs/configuration/dashboard/).
- Сопоставление товаров и монитор интеграции: специализированные страницы с `UnfoldModelAdminViewMixin`, явными разрешениями и `admin_site.admin_view`. Их URL регистрировать с проверкой конфликтов стандартного admin. [Пользовательские страницы](https://unfoldadmin.com/docs/configuration/custom-pages/).
- Дополнительный CSS кабинета отделить от публичного `site.css`. Пользовательские классы Tailwind требуют собственной сборки; стандартные компоненты и небольшой отдельный CSS позволят начать без второй сложной сборочной цепочки.
- Unfold предоставляет интерфейсные средства; сопоставление, очередь, редакционная модель и защита от дублей реализуются в FishSite.

## 5. Редактирование цены и действия с МойСклад

### Одно поле цены

Владелец изменяет поле **«Цена за кг»** в обычной карточке товара и нажимает «Сохранить». Не нужны переключатели режимов, обязательная причина, срок действия или отдельная кнопка возврата к МойСклад.

- `Product.price_per_kg` — единственная действующая цена сайта. Её используют каталог, рекомендации, корзина и новые заявки.
- Ручное сохранение работает через локальную БД, в том числе при недоступном API или остановленном worker. Цена должна быть положительной и укладываться в диапазон поля; автора и время записывать автоматически.
- Успешное применение изменившейся выбранной внешней цены или принудительная сверка **конкретного товара** обновляет это же поле. Обычное событие без изменения выбранной цены сохраняет ручное значение. Суточная, восстановительная и ручная сверки заменяют его даже при прежней внешней цене. Ошибка API или невалидный ответ оставляет текущую цену без изменений.
- Под полем объяснять, что ручную цену заменят изменение выбранного внешнего прайса или успешная сверка. Рядом — время последней успешной проверки и, при сбое, понятное сообщение. Источник последнего сохранения — справочная информация, не режим управления.
- После восстановления обмена цены обновляются автоматически по каждому успешно проверенному товару. Получение ответа от API само по себе не означает, что весь прайс восстановлен; нужна сверка всех связанных товаров, включая позиции без внешних изменений за время сбоя.
- Изменение через сайт не записывается обратно в прайс МойСклад. Постоянные изменения прайса владелец делает в МойСклад; админка позволяет продолжить работу во время сбоя.
- Сохранять только текущую цену и сведения о последнем изменении: источник, автора, время и редакцию для защиты от конфликтов. Отдельной истории цен нет. Право `change_product_price` входит в единственную роль владельца; отдельных редакторов нет.

Экспорт использует `OrderItem.price_per_kg_snapshot`: дальнейшая синхронизация не меняет цену уже принятой заявки. Изменившаяся цена в ещё не отправленной корзине требует повторного подтверждения по существующему сценарию.

Форма проверяет право изменения цены и использует общий сервис сохранения из [плана МойСклад](MoySklad-plan.md). Сервис сохраняет сведения о последнем изменении и защищает от перезаписи устаревшей формой; после подключения API тот же механизм используется для синхронизации. При конфликте форма показывает актуальную цену и сохраняет введённое значение для повторного решения владельца. Редактирование описания не должно возвращать прежнюю цену. Отдельная модель исключений и расчёт приоритетов цен не нужны.

### Сопоставление и восстановление

Показать существующую карточку, кандидата МойСклад, артикул, учётное название, единицу и цену. Не предлагать автоматическое подтверждение неоднозначного совпадения. Новая позиция сначала оформляется и остаётся неопубликованной.

«Повторить передачу» возобновляет ту же задачу. «Связать с существующим заказом» доступно при ручном разборе после проверки номера, состава и отсутствия занятой связи. При неизвестном результате предыдущей попытки сначала выясняется наличие документа по прежнему `syncId`; UI не создаёт новый документ или ключ самостоятельно.

Для начатой передачи без известного UUID есть «Проверить результат передачи»:
OTP, CSRF, непустая причина и подтверждение; POST ставит ту же задачу.
Worker только ищет по `syncId`, включая удалённые документы, без POST создания.
Найденный UUID сохраняется, в том числе при расхождении/удалении. Только полный
валидный пустой ответ при действующем lease снимает запрет исправления
идентичности и оставляет `manual_review` / `export_absent`; исправление или
повтор выполняется отдельно. Исходные снимки, контакты и согласие неизменны.

Перепривязка товара требует причины/подтверждения и журнала. Изменение цены сохраняется обычной кнопкой «Сохранить» вместе со сведениями о последнем изменении. Старые снимки не переписываются. Неисправная внешняя связь, архивный товар или недопустимая единица показываются как разные проблемы; остатки не участвуют в решениях.

### Состояния обмена

Различать время проверки доступа, успешной сверки каталога, конкретной цены, экспорта и heartbeat worker. Показывать возраст старейшей ожидающей заявки, число ошибок и время последней успешной проверки цен. Один успешный товар не означает актуальность всего каталога.

Полные контакты доступны только в защищённой карточке заявки. На дашборде и в диагностике не выводятся токены, тела API-запросов и необработанные исключения.

## 6. Модели и размещение кода

Модели ниже реализованы; их ограничения остаются контрактом кабинета.

| Модель / изменение | Назначение и ограничения |
|---|---|
| `Product`: редакционные поля | `display_order`, SEO. Существующие публичное название, slug, категория, описания, публикация и галерея сохраняются; хиты выбираются через `HomepageRecommendation`, прежний `is_popular` не используется |
| `Category` | SEO-поля с текущим fallback, сохранение плоской структуры |
| `Order` / `Inquiry` | Исходные обращения доступны только для чтения; служебные поля удалены миграциями, локальные статусы обработки не хранятся |
| `HomepageRecommendation` в `content` | Два явных слота главной, ссылки на товары, уникальность слота и товара |
| `ContentPage` | Одно поле текста для главной и информационных страниц; заголовок/SEO отдельно. Без конструктора, изображений и порядка; фиксированные ключи сохраняются. `ContentSection` — только архив |
| `SiteSettings` / `SiteLink` | Одна запись контактов/графика и добавляемые inline-ссылки (название, URL, логотип), доступные через право изменения настроек. Старые фиксированные ссылки и текст под логотипом подвала архивированы; новых настроек обложки нет |

Действия сотрудников записываются в существующий Admin LogEntry. Сохраняются ограничения удаления заявок и архива согласий, неизменяемость `OrderItem`, фиксированные ключи страниц и одно основное фото.

Внешний реестр `MoySkladProduct`, `MoySkladOrderLink`, `MoySkladTask`, `MoySkladWebhookInbox`, `MoySkladSyncState`/`MoySkladSyncRun`, ревизия цены, интеграционная блокировка `Product` и внешние снимки `OrderItem` добавлены по [плану МойСклад](MoySklad-plan.md). Админка использует их, не создавая дублирующих моделей.

```text
fishsite/backoffice/   # конфигурация Unfold, навигация, дашборд, доступ
catalog/admin.py       # товары, категории, фото и формы цены
orders/admin.py        # розничные заявки и их служебная обработка
inquiries/admin.py     # просмотр оптовых заявок, поиск и фильтры
content/admin.py       # страницы, контакты, рекомендации
integrations/admin.py  # отображение обмена и действия через сервисы
templates/admin/      # специализированные экраны кабинета
static/admin/          # изолированные стили кабинета
```

Модели и миграции остаются в соответствующих существующих Django-приложениях. `content` владеет содержанием страниц, `catalog` — каталогом, `orders`/`inquiries` — заявками. `fishsite/backoffice/` объединяет оформление и навигацию, не забирая в себя доменную логику.

## 7. Права, вход и журнал действий

| Роль | Разрешения |
|---|---|
| Владелец | Товары и цена, контент, рекомендации, просмотр заявок |
| Разработчик | Существующий `is_superuser` для технического обслуживания; это не прикладная роль кабинета |

Владелец — обычный активный `is_staff` с группой разрешений, без `is_superuser`. Техническое обслуживание выполняется существующим superuser; отдельных прикладных ролей нет. Команда `create_backoffice_owner <username>` создаёт обычного владельца с интерактивным паролем; `sync_backoffice_roles <username>` назначает группу существующему пользователю. При лишних правах вне роли команда откажет и сохранит их, чтобы технический администратор мог проверить аккаунт. Права владельца охватывают каталог и цену, CMS, чтение/обработку заявок, рекомендации, простой экран МойСклад, сопоставление, сверки и исправление передачи. Проверка подключения, управление потоками, одобрение передачи и подробные модели диагностики требуют `is_superuser`; прежние grants владельца не обходят эту границу. Проверять права в POST-обработчиках и сервисных действиях; скрытая кнопка не является защитой.

Все изменения — POST с CSRF. Массовое скрытие и перепривязка показывают краткое подтверждение последствий. Обычное сохранение текста или цены не требует дополнительного диалога. Удаление заявок, снимков и архива согласий остаётся закрытым.

Для рабочего запуска обязательны HTTPS, secure cookies, корректные proxy-заголовки, ограничения попыток входа по учётной записи и IP, TOTP для административных URL и сохранённые резервные коды. Эти механизмы настроены в Django; env-переменные HTTPS остаются выключенными для локального HTTP по умолчанию. [Требования к защите AdminSite](https://django-two-factor-auth.readthedocs.io/en/stable/implementing.html).

Токен МойСклад не показывается в формах и не передаётся браузеру. Права API-пользователя и защита webhook определены в [плане МойСклад](MoySklad-plan.md); оператор кабинета работает через ограниченные сервисные действия.

Юридические тексты сейчас принадлежат Markdown-файлам и архиву редакций. В кабинете сохраняется read-only доступ; перед вводом обмена процесс передачи контактов и сроки хранения обновляются в соответствующих документах совместно с интеграцией.

Постоянный production-приёмник, окончательные

При первоначальной реализации 12.10.2026 по запросу заказчика новые тесты
админки не добавлялись и набор не запускался.
15.10.2026 заключительный полный набор прошёл **321/321** за 47,296 с,
с созданием и удалением тестовой БД. Включены гонки PostgreSQL,
восстановление экспорта и inbox, 12 acceptance-сценариев и независимость SMTP
от невалидной конфигурации МойСклад. Прежние 266 тестов / 28 failures /
5 errors — исторический результат до согласования фикстур; OTP, защита цены,
исторические модели и границы запросов сохранены.
Системные проверки и сервисные тесты не заменяют ручную проверку форм и OTP.
Обычную практику панели проводить на выделенных синтетических данных без
рабочих ключей; выполненная живая проверка использовала отдельную БД,
namespace и намеренно выделенные внешние данные. Оставшиеся сценарии
рабочего ввода сохраняются в [плане МойСклад](MoySklad-plan.md).

Заключительная локальная проверка «Проверить результат передачи» выполнена
в отдельной проверочной БД с синтетической `R-59E7261908`. Обычный владелец
без superuser вошёл по паролю и OTP; POST без CSRF получил 403, форма с
причиной и подтверждением вернула успешное сообщение. Сохранены прежние
задача, `syncId`, неопределённая попытка и снимок 2200 ₽ × 1 кг; добавлен
`request_export_resolution`. Все четыре потока этого контура выключены,
API-worker отсутствовал: внешний поиск и SMTP не выполнялись. При 390 px
и размере текста 200% форма не переполняет экран, обязательные поля и кнопка
доступны. Это ручная проверка интерфейса, а исполнение поиска подтверждено
автоматическими recovery-сценариями.

### Демонстрация владельцу

1. Войти под обычным владельцем: проверить переход после пароля к настройке TOTP, завершить регистрацию, сохранить резервные коды, выйти и войти повторно с OTP. Проверить профиль и восстановление резервным кодом на синтетическом аккаунте.
2. Убедиться, что владелец не superuser и не видит пользователей, группы, почтовую очередь или секреты; открыть напрямую защищённую страницу без прав и убедиться в отказе.
3. Найти товар, изменить публичное название/описание и цену, загрузить фото, выбрать основное изображение и порядок, затем проверить карточку и категорию сайта. Переключателя хитов и отдельной отметки популярности быть не должно.
4. Выбрать и поменять местами два рекомендуемых товара. Проверить метку «Хит» только на главной, дубль, скрытие и сохранение скрытого товара в слоте без публичного fallback.
5. Через «Содержание сайта» изменить единый текст главной, «О компании» и доставки; убедиться, что контактов нет в редакторе страниц; отдельно изменить общие контакты и график. Проверить общие данные в шапке, на главной и странице контактов; в подвале не должно быть контактных данных, а на странице контактов — второй карточки. Проверить добавление/удаление ссылки, пустой адрес, название без логотипа и логотип с доступным названием. Убедиться, что отдельного раздела «Обложка главной» нет, кнопка главной всегда ведёт на `#assortment`, а Markdown юридических страниц и согласий не меняется.
6. Изменить цену одновременно с описанием; затем открыть устаревшую форму после другого изменения цены и убедиться, что показана понятная ошибка, а введённое значение не потеряно. Проверить, что цена и сумма старой заявки не меняются.
7. Открыть розничные и оптовые заявки: проверить контакты, согласие и снимки. Проверить отсутствие вкладки работы менеджера, редактируемых служебных полей, кнопок сохранения, фильтра просмотра и действия отметки прочтения. Оба счётчика на дашборде показывают общее число обращений; поддельный POST изменения заявки возвращает 403.
8. Открыть «Интеграция → МойСклад»: без конфигурации «Не подключено», с конфигурацией — локальная диагностика. GET не вызывает API; разрешённый POST фиксирует автора и ставит работу в очередь.

Проверки цен, повторной сверки после сбоя, идемпотентного экспорта, восстановления после неоднозначного ответа и подтверждения наличия менеджером остаются отдельными критериями интеграции. Живые результаты 15.10.2026 и непокрытые сценарии фиксируются в [журнале реализации](MoySklad-implementation.md); проверка панели сама по себе их не закрывает.

## 10. Включение и ручная приёмка

Перед изменением рабочей базы подтвердить, что окружение указывает на нужную БД, сохранить backup БД и media, затем применить добавочные миграции и проверить существующие карточки/URL/заявки. Миграции не создают пользователя и не заполняют контактные данные владельца.

```sh
uv sync --locked
.venv/bin/python manage.py check
# Сначала проверьте DB-настройки и наличие проверенной резервной копии.
.venv/bin/python manage.py migrate
.venv/bin/python manage.py collectstatic --noinput
# Создайте обычного владельца; пароль вводится интерактивно.
.venv/bin/python manage.py create_backoffice_owner OWNER_USERNAME
# Либо назначьте роль уже существующему обычному пользователю.
.venv/bin/python manage.py sync_backoffice_roles OWNER_USERNAME
```

Замените `OWNER_USERNAME` выбранным именем. Команда назначения не создаёт пользователя, не меняет пароль и отказывает superuser, отключённым аккаунтам и пользователям с лишними правами. Создание нового владельца проверяет пароль штатными валидаторами Django; не передавайте пароль в командной строке. Разработчик использует свой существующий superuser для технического обслуживания, владелец входит под отдельной обычной учётной записью.

После назначения откройте `/admin/`. Вход без зарегистрированного устройства перенаправит владельца на `/two_factor/account/two_factor/setup/`; завершите настройку приложения TOTP, сохраните резервные коды и после выхода проверьте вход с OTP. Страница профиля: `/two_factor/account/two_factor/`; резервные коды: `/two_factor/account/two_factor/backup/tokens/`. Храните коды вне сайта. Самостоятельное отключение обязательной защиты в браузере недоступно. Процедура восстановления после потери устройства и кодов описана в [руководстве кабинета](backoffice.md#восстановление-доступа).

Последовательность практического ввода: применить миграции → назначить группу существующему владельцу → пройти настройку 2FA и ручную приёмку → выдать владельцу URL и инструкции. Перед доступом к реальным контактам подтвердить HTTPS и secure cookies в production.

На 15.10.2026 шесть добавочных миграций МойСклад применены в рабочей `fishsite` после backup с проверкой восстановления, роль Owner синхронизирована до 43 прав. Это отдельный этап после первоначальной проверки кабинета 12.10.2026. По последующему запросу владельца в БД разрешены все четыре потока временной демонстрации и явно начат экспорт после 13 исторических заявок. Их ретроспективной передачи нет. Установка Unfold и миграции сами по себе обмен не включают; значения флагов окружения по умолчанию остаются `False`.

При откате интерфейса сохранять новые данные, связи, текущие цены, снимки заявок и очередь. Не откатывать схему с потерей контента. Предыдущая версия admin допустима только при сохранении тех же прав, 2FA и запрета редактирования снимков и служебных полей интеграции, а также правил сохранения цены. Если это не обеспечивается, закрыть административный доступ на время исправления, сохранив работу сайта и фоновых сервисов. Остановка/откат интеграции выполняется отдельно по её плану.

## 11. Оставшиеся решения

- Владелец явно разрешил короткие демонстрационные описания и прежние иллюстрации для 39 опубликованных карточек. Они помечены «Демонстрационное фото»; для постоянного запуска остаются подтверждённые контакты, график, окончательные тексты и материалы.
- До публичного доступа проверить production HTTPS, secure cookies, доставку статики и процедуру восстановления TOTP.
- Для постоянного МойСклад перенести приёмник и собственный вебхук с временного ngrok на production HTTPS, завершить постоянные материалы и юридические сведения. В демонстрации экспорт уже явно начат, `00088` и `00089` размещены в «Холодном копчении»; завершённая замена каталога описана в [проверке ассортимента](MoySklad-catalog-review.md). По [официальной таблице](https://www.moysklad.ru/subscription/), проверенной 15.10.2026, на подтверждённом владельцем «Базовом» число документов не ограничено; 100 документов — предел бесплатного тарифа. При смене тарифа/индивидуальных условий перепроверить контракт; `document_limit` пока подтверждён mock API, `1070` не означает исчерпание числа документов.

Тариф, API-права, тип цены, единица кг, организация, контрагент и налоговые настройки проверены в отдельном живом контуре; контракт и оставшиеся критерии ввода находятся в [плане МойСклад](MoySklad-plan.md). Остатки, оптовый прайс на сайте, клиентский кабинет, онлайн-оплата, произвольный конструктор страниц и расширенная аналитика не входят в этот объём.
