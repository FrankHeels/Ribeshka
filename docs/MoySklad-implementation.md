Рабочая декомпозиция плана [MoySklad-plan.md](MoySklad-plan.md), начата 15.10.2026.
Требования к поведению остаются в плане; этот документ фиксирует порядок,
границы ответственности и доказательства приёмки реализации.

На 15.10.2026 код обмена и панель реализованы; полный автоматический набор
проекта проходит: **321/321**. Живая приёмка заказа, вебхука цены и статуса выполнена в
отдельном проверочном контуре. Основная БД подготовлена; по последующему
решению владельца опубликованы 39 демонстрационных карточек и включён временный
обмен через ngrok. Постоянное развёртывание остаётся отдельным этапом.

последовательно, поскольку тестовый кластер допускает одно имя БД.

## Архитектурные решения

- Код обмена размещается в `integrations/moysklad/`; SMTP и API используют
  отдельные долговечные очереди и процессы. HTTP не выполняется в публичном POST.
- Новые модели интеграции регистрируются в приложении `integrations`.
  Миграции добавочные; исторические заявки автоматически не ставятся в очередь.
- `Product.integration_block_reason` дополняет решение владельца о публикации;
  `mapping_revision` входит в подписанное подтверждение корзины.
- Единственным способом применения цены остаётся `change_product_price()`.
  Порядок блокировок: товары по ID, затем внешние записи, затем задача.
  HTTP выполняется между чтением редакций и короткой транзакцией применения.
- `settings.MOYSKLAD` содержит серверную конфигурацию. Тестовый профиль
  использует только синтетические значения, моки или loopback API.
- Фиксированный API host, проверенные UUID и допустимые пути исключают запросы
  по произвольным `href`. Логи содержат безопасные коды, без payload и секретов.
- Публичные результаты розницы и опта сохраняют случайные токены, 404 для
  неизвестного токена и приватные заголовки; внутренние номера доступны владельцу.

## Граница живого ввода

Автоматические проверки выполняются без рабочего токена в изолированном
PostgreSQL на порту 15432. Живые проверки выполнены отдельно от них, в БД
`fishsite_moysklad_01a13f50` на порту 5432, с синтетическими контактами и
отдельными окружением и namespace. SMTP в этом контуре отключён.

Фактические UUID аккаунта, RUB, kg, розничной цены, организации, общего
контрагента и начального статуса проверены чтением API. Основной контур
использует собственный постоянный namespace. Существующий API-токен владелец
подтвердил как административный; отдельный административный токен необязателен.

Проверка подключения не заменяет регистрацию HTTPS-приёмника и явную границу
экспорта. Для текущей демонстрации они выполнены: свой вебхук активен, четыре
потока разрешены в БД, `export_started_at=2026-10-15T19:23:04.650398Z`.
Базовые флаги `.env.example` остаются выключенными; включение не происходит
только из-за наличия токена.

## Подтверждённые внешние контракты

- `salePrices[].value` и цена позиции заказа выражены в копейках;
  единица товара задаётся ссылкой `uom`, а не флагом `weighed`:
  [схема товара](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/dictionaries/_product.md).
- `customerorder` поддерживает `syncId`, `description` до 4096 и
  `shipmentAddress` до 255; «без НДС» в позиции задаётся `vat=0`,
  `vatEnabled=false`:
  [схема заказа](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/documents/_customerOrder.md).
- Уведомление требует 200/204 за 1500 мс, содержит несколько событий и
  стабильный `requestId` при повторе:
  [контракт вебхука](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_webhook.md).
- `X-Lognex-Retry-After` задаётся в миллисекундах:
  [общий контракт API](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/_general.md).

## Проверки

Первоначальные проверки писал Luna tester до реализации Sol; исторический
прогон девяти модулей дал **146/146**, включая пять гонок с отдельными
соединениями PostgreSQL. Исправление ссылки в email имело ожидаемый red
(1 fail, 1 pass), затем green: используется HTTPS-origin без секрета приёмника,
а при отсутствии подходящего URL — безопасный локальный путь.

Заключительную фазу проверял Sol tester (xhigh). Два сценария недоступной
конфигурации мониторинга SMTP дали ожидаемый red, затем green; ещё один red
для невалидного IPv6 URL также исправлен. Ошибка конфигурации МойСклад не
останавливает розничные и оптовые письма: монитор выдаёт безопасный
`monitor_unavailable` с интервалом не чаще минуты. Узкая обработка
`ImproperlyConfigured` не скрывает ошибки БД.

Восстановление передачи проверено модулем `tests.test_moysklad_recovery`
(14 сценариев): crash после POST до локальной записи, истёкшие lease,
действия владельца, конкурентное оформление, cursor частичного inbox,
очистка и атомарный отказ webhook с 503. Две регрессии независимого ревью
сначала дали ожидаемый red; после исправления recovery и три SMTP-сценария
прошли **17/17** за 2,182 с. Заключительное Astra-ревью существенных
замечаний не выявило.

Модуль `tests.test_moysklad_acceptance` прошёл **12/12** за 2,944 с.
Он дополняет готовое поведение; три первоначальных падения были ошибками
тестовых часов, а не функциональным red. Прежние фикстуры приведены к
текущему контракту; отдельный legacy-прогон — **78/78**. Обязательные OTP,
ограничения цены, исторические модели миграций и границы числа запросов сохранены.

Итоговая команда 15.10.2026:

```sh
.venv/bin/python manage.py test tests --settings=fishsite.settings_test --noinput
```

Результат — **321/321**, 47,296 с, с `Creating test database`, `OK` и
`Destroying test database`. Полный вывод сохранён в
`/private/tmp/fishsite-moysklad-final-full-suite.log`. Предыдущий результат
266 тестов / 28 failures / 5 errors относится к состоянию до согласования
фикстур и больше не является текущим блокером.

`manage.py check --settings=fishsite.settings_test` проходит. Реальная команда
`makemigrations --check --dry-run` через отдельный закреплённый проверочный
профиль `/private/tmp/fishsite_moysklad_validation_manage.py` завершилась с
`No changes detected`, кодом 0; рабочая БД не использовалась.
Правила запуска — [изолированное тестовое окружение](test-environment.md).

### Локальная проверка действия восстановления

Обычный `FishSite Owner` без superuser вошёл в отдельный проверочный контур
по паролю и OTP. POST формы «Проверить результат передачи» без CSRF вернул
403; с непустой причиной и подтверждением — редирект в заявку с сообщением
об успехе. У синтетической `R-59E7261908` та же задача 52 стала `pending`,
`attempted=True` сохранился, добавлены `resolution_requested=True` и аудит
`request_export_resolution`. UUID остаётся неизвестным, исходные 2200 ₽ × 1 кг
не изменены. При ширине 390 px и тексте 200% `scrollWidth=clientWidth=390`,
обязательные поля и кнопка доступны. Четыре потока этого контура выключены,
API-worker отсутствовал; HTTP провайдеру и SMTP не выполнялись. Исполнение
поиска проверяется recovery-тестами, а не этим браузерным действием.

### Оставшиеся границы проверки

Постоянный HTTPS-приёмник и эксплуатация вне временного ngrok ещё не настроены.
Docker Compose и `nginx -t` не проверены: соответствующие исполняемые программы
недоступны в этой среде. YAML разобран, но это не проверка запуска контейнеров.
Положительная проверка [официальной тарифной таблицы](https://www.moysklad.ru/subscription/)
15.10.2026 подтвердила отсутствие лимита числа документов у «Базового», который
владелец указал для аккаунта. Ограничение 100 документов относится к бесплатному
тарифу. Исчерпание числа документов поэтому не является воспроизводимой
приёмкой текущего тарифного контракта. При смене тарифа/индивидуальном лимите
потребуется заново проверить условия и структурный ответ Remap; `1070`
не означает исчерпание числа документов.
Семантическая пауза `document_limit` проверена с mock API.
