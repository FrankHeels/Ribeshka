- `db`, `web`, `nginx`, SMTP `worker` запущены; healthcheck БД и web успешны. `compose config --quiet` и `nginx -t`

   `certbot-deploy-hook.sh` установлен в `/etc/letsencrypt/renewal-hooks/deploy/fishsite-nginx`.

   рабочий сервер использует только доверенный сертификат Let's Encrypt.
3. SMTP теперь принят: поддержка открыла исходящий 465, `check_notification_smtp` успешно проверил
   подключение, TLS и AUTH. Проверена вся очередь: только одна согласованная синтетическая заявка.
   Однократный `process_notifications --once` обработал ровно одну задачу, `sent`, `attempt_count=1`.
   Пользователь подтвердил получение письма. Письмо повторно не отправлять.
4. Worker уведомлений запущен профилем `notifications`, в журнале `worker_started`, очередь содержит
   только одну уже отправленную задачу. МойСклад выключен, его credentials не переносились.

   и Docker. Проверены срабатывание правила из worker, успешный SMTP preflight на 465 и сохранение
   правил после перезагрузки. Это ограничение SMTP-портов, не общий белый список исходящих адресов.
5. Независимый мониторинг и аварийные оповещения ещё не настроены.
   Расписание и постоянное внешнее хранилище копий также не настроены. Пользователь явно принял эти
   ограничения для суточного публичного теста и после приёмки разрешил открытие всем посетителям.
   Перед постоянным запуском закрыть оставшиеся условия контракта; автоматическое отключение VPS
   и удаление данных не настраивались.

Пользователь явно разрешил отправку обращений. 24.10 созданы и проверены в панели:

- [DNS №12913709](https://hosting.timeweb.ru/tickets/12913709): удалить отсутствующую в редакторе AAAA,
  сохранить A на VPS; приложена безопасная ошибка ACME без credentials.
- [SMTP №12913713](https://timeweb.cloud/my/support/tickets?ticketId=12913713): разрешить только исходящий
  TCP 465 для Mail.ru, не открывать другие SMTP-порты. SSH-доступ поддержке не выдавался.

После ответа поддержки перепроверить сами DNS/SMTP, а не считать обращение подтверждением исправления.

## Безопасное продолжение

Команды на VPS выполнять из `/opt/fishsite/current/deploy/production`:

```sh
docker compose ps
docker compose config --quiet
docker compose exec -T nginx nginx -t
```

Процедура TLS и пересоздания контейнеров: [VPS README](../deploy/production/README.md).
Не включать профили worker до проверки SMTP и очереди. `restart` не перечитывает env;
после изменения env пересоздать соответствующие процессы и проверить upstream Nginx.

Для просмотра после TLS используй [рибешка.рф](https://xn--80abmkm6a0d.xn--p1ai/).
Следующая команда относится только к bootstrap HTTP до включения HTTPS:

```sh
ssh -o IdentitiesOnly=yes -i ~/.ssh/fishsite_timeweb_ed25519_v2 -N -L 127.0.0.1:18080:127.0.0.1:8080 fishdeploy@186.246.28.83
```

После включения HTTPS этот HTTP-туннель не подходит для браузерных cookies/POST.
Остановить ранее запущенный туннель — `Ctrl+C`.
При первом подключении сверить Ed25519 host fingerprint:
`SHA256:TA+Za33ZmyuEwgRrrei/s6S+M1rWuiEien+RzSl/1w8`.
