# Защита публичных форм

Общие правила розничной и оптовой заявки. Реализация токенов, ограничений
и DB-независимого ответа — [integrations/public_forms.py](../../integrations/public_forms.py).

## Идемпотентность

Каждая открытая форма получает UUID-ключ и подписанный токен с видом формы,
ключом, nonce серверной сессии, снимком и редакцией согласия. Формы и вкладки
имеют собственные ключи; токен другой сессии не принимается.

После проверки подписи уже принятый ключ ищется до валидации корзины/полей
и расходования лимита. PostgreSQL advisory lock сериализует сохранение по
одному ключу. Конкурентный повтор создаёт одну заявку и одну почтовую задачу;
после очистки корзины или потери ответа возвращается прежний результат.

При ошибке сохранения исходный ключ и введённые контакты остаются для повтора.
Если результат commit неизвестен, повтор исходного POST либо находит принятую
заявку, либо создаёт её один раз. При полной недоступности БД ответ 503
рендерится без сессии, каталога и DB-зависимых context processors.

## Редакция согласия

[Исходный Markdown согласия](../legal/personal-data-consent.md) при первом
использовании архивируется под SHA-256 идентификатором.
[ConsentRevision](../../content/models.py) хранит неизменяемый текст, а
подписанная форма и новая заявка ссылаются на конкретную редакцию. Ссылка
согласия в форме открывает именно её.

Изменение Markdown после показа формы не подменяет принятый текст. Повтор
ошибки и подтверждение обновлённой корзины сохраняют подписанную редакцию.
Неизвестная редакция или токен без версии требуют новой формы с незаполненным
согласием. Идемпотентный повтор принятого ключа не меняет прежнюю ссылку.
Для старых заявок без ссылки версия задним числом не назначается.

Это фиксация принятого текста, а не свидетельство юридической готовности:
проекты в `docs/legal/` содержат незаполненные поля. Их использует приложение;
изменение текста создаёт новую редакцию для последующих форм.

## CSRF и ограничение частоты

Изменения корзины и отправка заявок требуют CSRF и серверной валидации.
Обе формы используют honeypot `website` и общий для процессов счётчик PostgreSQL;
адрес хранится как HMAC. Параметры `PUBLIC_FORM_RATE_*` задаются в
[настройках](../../fishsite/settings.py).

При прямом подключении используется `REMOTE_ADDR`. За доверенным Nginx
`DJANGO_TRUST_X_REAL_IP` включается только вместе с перезаписью `X-Real-IP`
самим прокси: иначе клиент может выбирать адрес счётчика.

Ошибки полей возвращают 400, изменение снимка корзины — 409, превышение
лимита — 429, временная ошибка БД — 503. Ответы с формами и результатом
заявки запрещают кеширование. Представление ошибок и ограничения полей —
[контракт frontend](../frontend-contract.md); атомарное сохранение —
[сценарии заявок](order-flow.md).
