# Email-уведомления

Открывай эту страницу при настройке SMTP, запуске worker или разборе outbox. Заявка и
`NotificationOutbox` сохраняются одной транзакцией; отправка происходит отдельным процессом
после commit. Набор переменных и defaults задают [`.env.example`](../../.env.example) и
[настройки](../../fishsite/settings.py).

## Безопасный запуск

1. Проверь адрес БД процесса и список готовых задач: `process_notifications` обрабатывает всю
   готовую очередь выбранной базы.
2. Выполни `.venv/bin/python manage.py check_notification_smtp`. Эта команда принимает только
   текущий профиль Mail.ru, открывает TLS/AUTH соединение и закрывает его; письмо, БД и outbox
   она не трогает.
3. Запускай `.venv/bin/python manage.py process_notifications` только после проверки БД,
   получателя и очереди. Это постоянный процесс. `--once` обработает все задачи, готовые сейчас,
   и выйдет.
4. Проверь безопасное событие worker и состояние записи. Для проверки реального письма используй
   отдельную синтетическую БД по [процедуре Mail.ru](../mailru-smtp-practical-test.md), не
   рабочую очередь.

При изменении SMTP-настроек останови worker, обнови среду процесса, повтори preflight и затем
запусти новый worker. Перезапуска одного контейнера недостаточно, если его environment не
перечитан.

## Границы доставки

- `NotificationOutbox` — долговременная очередь PostgreSQL. `pg_notify` только будит слушателей;
  worker устанавливает LISTEN до первого сканирования. При старте, reconnect и по таймеру
  он проверяет таблицу, поэтому пропущенный сигнал сам по себе не теряет задачу.
- Worker захватывает задачу короткой транзакцией с lease и token владельца, затем отправляет без
  удержания блокировки БД. Только текущий владелец действующего lease может зафиксировать
  результат.
- SMTP timeout ограничивает отдельную сетевую операцию, а не полное время отправки письма;
  общего deadline нет. Долгий вызов может пережить lease: письмо может быть принято SMTP, а
  результат уже не сохранится, после чего задача может отправиться повторно. Поэтому нельзя
  обещать доставку ровно один раз.
- Временные сбои повторяются по конфигурации окружения. Постоянные/неизвестные ошибки и
  исчерпание лимита переводят запись в `manual_review`; по истечении lease задача с исчерпанным
  лимитом не возвращается в автоматическую отправку.
- Ручной повтор доступен только пользователю с правом `change` и только для `manual_review`.
  Действие сбрасывает счётчик и безопасный код ошибки, возвращает запись в `pending`, будит
  worker и фиксируется в Django Admin Log. До повтора устрани причину и проверь риск дубликата.
  `sent` и активный `processing` этим действием не сбрасываются.
- `sent` означает принятие письма SMTP-транспортом, а не попадание во входящие. Неопределённый
  ответ может привести к повтору с тем же номером заявки.
- Worker-логи содержат результат и безопасный код ошибки, но не контакты, текст письма,
  credentials или исходное SMTP-исключение.

Источник очереди и схемы — [слой данных](../data-layer.md); атомарное сохранение заявки —
[сценарии заявок](order-flow.md). Worker также отправляет уведомления об инцидентах МойСклад, но
не выполняет сам API-обмен; см. [эксплуатацию МойСклад](../moysklad-operations.md).
